## Decisions

D1. **Hash id 17 and the Go order.** `Modules.Infrastructure` is the 17th pointer of the row (`spec-config.md` 3.1: Settlements 11, Storage 12, Employment 13, Tenure 14, Credit 15, Risk 16, Infrastructure 17, Insurance 18, Polity 19, Fiscal 20, Institutions 21, Policy 22, Saving 23, Technology 24, Estates 25). Its Go line is appended after `Tenure` (the last pointer in `Modules` today) in `Modules`, `canonical` and `modulesOn`, with the comment `Its hash id is 17, whatever its place in this struct` (N-347); its pair goes into `pairsLastModules` between id 15 and id 19 (ascending ids; the function comment, which says "ids 15, 19, 24 and 25", is edited). The field ids of the new types are their declaration order, `Label` having none: `Infrastructure` has `Classes` 1, `Initial` 2; `FacilityClass` has `ID` 1, `Kind` 2, `Durability` 3, `Decay` 4, `WearPerUse` 5, `Capacity` 6, `BoostBP` 7, `Modes` 8, `Resource` 9, `Store` 10, `Needs` 11; `InitialFacility` has `Region` 1, `Class` 2, `Toward` 3, `Role` 4, `Count` 5; `FacilityBuild` has `Class` 1, `Toward` 2; `FacilityRepair` has `Class` 1, `Units` 2. `Recipe` takes the next free ids after `Draws` 9: `Needs` 10, `Builds` 11, `Repairs` 12, written **only while the module is on** (the `resources bool` of `pairsRecipe` is the precedent: it becomes a small flags value, not a third boolean), so a clause in a configuration that fails validation for want of the module changes no hash (CFG 8.2.3). `Role` gets no field from this module. Phase 1 adds the row of CAP to `spec-config.md` 8.2.2 before `TestInfrastructureHash` is written, as 8.2.2 requires. Blocks and rows are written when non-nil; `Decay` 0 and `WearPerUse` 0 are written (they are values, not defaults to omit: a class in a file with `decay = 0` is the same class). The effect tables, the counters and the clamp are state or derived and are not hashed.
D2. **One position, no draw.** P8.3b is inserted after P8.3 (`p83Regen`) and before P8.3c (`p83cTechnology`); P8.3a (LND) is built later and is inserted between by LND PR 5, so the call line of CAP does not move: the row is `{"P8.3b", "CAP", line}` after `{"P8.3", "RES", line}`. The module takes no word of the stream at any position or call (FR-CAP-002; test `TestInfrastructure_NoDraws`); every iteration is over the sorted slice, ties by ascending `FacilityID`. The tables are rebuilt from the records, never incrementally (CAP 6.4.3).
D3. **A facility is not per-agent state.** `agentJoined` and `agentRoleChanged`'s only use is the store facility's role-change ruin (D8); no per-agent slice is hosted (N-128); no `relocationRefusal` row (N-090, 7.5): a test pins that a site, route and ground owner relocates and a store owner is refused by STO's `has_store` as before.
D4. **The section is tag 27.** One section, `Facilities`, present only with the module on: the next facility ID, the count, and the records in ascending ID (15.1). The effect tables and the per-tick counters are derived and rebuilt after `loadFacilities` and after tag 15 (resources), 17 (transport) and 3 (agents, stores) are in. **Trap (R2):** `loadResources` checks at its end that every stock lies inside its effective capacity (`resources.go:499`); that check runs before tag 27 is read and would call a stock that sits above the facility-less capacity of a ground-improved endowment corrupt. Phase 5 moves the check to the cross-checks that run after all sections (the LND precedent for tenure), in the fixed order of CHK 6.2.
D5. **A hook is one nil-safe or guarded call.** `fillAgentView` is at CCN 10 and `positionsTail` at CCN 10 today; `removeAgent` is at CCN 8. So the removal step, the view filler and the role-change ruin are **unguarded, nil-safe** calls (`w.dropFacilities(a)`, `w.fillFacilities(v, a)`; the `dropClaims` precedent: Lizard counts no branch for a call) and P8.3b needs the split of `positionsTail` (hook 2, R3).
D6. **The layers write through function values and arrays that the module sets, never into another module's slot.** TRN gets `transportState.layer func(from, to RegionID, mode ModeID, slot int64) int64` (nil: the slot value) used by dispatch and `Travel`, not by `Slots()`, so the consumer's value is returned unchanged (FR-CAP-021). RES gets `resourcesState.facilityBP []int64` indexed by cell (nil: 0) passed as the third argument of the existing `endowment.EffectiveCapacity`. STO's `facilityCount` is set to a method of the module. PRO reads the site capacity and the limits through fields of `startReq`. Each is set in `wireSeams` (after the module is built), the construction hook class (d).
D7. **Reasons are constants of `event.go`.** Six new `Reason` constants (`no_facility`, `not_unlocked`, `facility_cap`, `no_target`, `store_refused`, `nothing_to_repair`), with limit codes appended in `production.go` in the master order of CAP 4.2.2: `limitNoFacility` between `limitNoTool` and `limitNoInput`, and the five others after `limitRentFunds` and before the room reason; `deferredProduction` loses the six names. The kinds (`added`, `built`, `repaired`, `installed`, `transferred`, `ruined` and, by the owner's decision at PR 2, `adjusted` for a non-ruining `AdjustFacilities`) are a new closed set `FacilityKind`; the causes reuse the existing `Cause` type: `consumer`, `role_changed`, `facility` and the new constants `recipe`, `initial`, `decay`, `use`, `owner_removed` are appended (Phase 3 greps `event.go` for any that exist).
D8. **Store facilities are STO's stores.** The install calls `addStore(a, class, CauseFacility)` at P8.3b (or in the call that creates it), the ruin calls `removeStore(a, class, CauseFacility, true)` (forced) and `GoodsListed` is its return; a role change that ends a store (STO's `roleChangedStorage`) ruins the store facilities of the agent in ascending ID after the `RoleChanged` event and STO's `deliverEnded` (CAP 5.4.3). **The removal of an owner (R4):** CAP 7.1.1 says "storage's `StoreChanged` comes first", but STO's `dropStorage` emits no event (`storage.go:343`: the stores end with the account). Phase 1 reconciles the text with the code and decides the one that changes; the recommendation (Q6) is that CAP emits `FacilityChanged` (`ruined`, `owner_removed`, `GoodsListed` 0) alone and the spec sentence is amended, because STO's no-event rule is merged and tested.
D9. **Counters only under an observer.** `FacilityLimited` fields (`Served`, `Cut`, `Refused`, `Voided`, `Pending`) are per-tick counters kept per (region, class) only when `w.obs.supplied` (observability-and-logging.md 4.5); `used(principal, class)` and `served(f)` are not counters but state of the step and are kept always (they bound a start): both are arrays cleared at P8.6, never saved, and allocate nothing per call (NFR-CAP-002).
D10. **Rule constants beside their code** (architecture.md 9.6): the four kinds, the roundings (`floor` a gain, `ceil` a capacity), the capped sum, the most-worn-first order with ties to the lower ID, the order of the step of 6.3.2, the commissioning at P8.3b, the inheritance by the estate, the reasons and causes of 14.2, the position. No default macro constant is added (N-027): `Decay` 0 and `WearPerUse` 0 are the off values, and the overlay's numbers are labelled placeholders.
D11. **Existing goldens do not move.** `testdata/golden/off/`, the pinned hash and `testdata/checkpoints/` stay unchanged at every PR (N-217); a diff there is a failure of the change, not a golden to regenerate. `testdata/golden/infrastructure/` is **new files**, recorded once in PR 5. `golden/all/` and the all-on checkpoint fixture are not touched.
D12. **Coverage row.** `internal/facility 90`, added in Phase 2 with the package; `scripts/ci/selftest.sh` run.
D13. **Sentinels** are root sentinels matched with `errors.Is` (N-075). New: `ErrFacilityShape`, `ErrFacilityNoCost`, `ErrFacilityHolder`, `ErrFacilityCount`, `ErrFacilityCap`, `ErrFacilityLocked`, `ErrFacilityTarget`, `ErrFacilityRegion`, `ErrFacilityOwner`, `ErrFacilityNotTransferable`, `ErrUnknownFacility`, `ErrUnknownFacilityClass`. D14. **A build or a repair is an ordinary job.** No new job type, no new account, no new reason; the clause is read from the recipe at the completion (15.5).
