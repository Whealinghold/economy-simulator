## Decisions

- **D580** `internal/verdict` is standard library only, imports neither the root, `config/`, `indicator/` nor any other `internal/` package, has no `*slog.Logger` and no event, and has no float type or float function of `math`, and no `math` import at all except where D587 says a range check replaces it (architecture 5.1, 2.9, 3.5; STY 9.1, 13.1, 22; NFR-STY-004, FR-STY-006, 080).
- **D581** Input is plain: `Point{Tick, Value int64}` series and flag series copied inline by the caller from IND results (architecture 2.9; STY 6.1.1). A detector takes one `Input` struct (named fields, no map) and a `Thresholds` value and returns a `Verdict`; it draws nothing and reads no clock (FR-STY-080).
- **D582** `Thresholds` is an ordered list of `Key{Name string, Value int64, Set bool}` in the order of STY 6.2 (the shared keys `stale_max_bp`, `active_min_bp`, `min_windows` last); the loader fills it from `regimes.toml`. A key with no `value` line is unset and a detector that needs it returns `unknown` with reason `threshold unset` (STY 6.5.1; FR-STY-060, 070).
- **D583** Verdict classes `none`, `detected`, `unknown` and the closed set of `unknown` reasons (`windows`, `stale`, `active`, `threshold unset`, `reference missing`, `needs a longer run`, `clamped`, `outcomes`: the last two for the blind-spot fields of 4.3 on the detectors that read an index or a share) are rule constants beside their code (STY 6.1.2, 11). The comparison is "at or above". R2, R4, R5b and R9 are never made `unknown` by low activity; `Stale` makes R1 and R9 `unknown` only where the rule would return `none` (STY 4.3; FR-STY-060).
- **D584** Windows: R1 to R4, R8, R9 read whole year windows counted from tick 0, first included, warm or cold; R6 reads the season or year windows the caller passes (the S05 pair uses seasons, STY 6.2); `min_windows` 3. R5a, R5b and R7's completion test read one-tick series and return `unknown` for a series shorter than their own count key (`pinned_ticks`, `freeze_ticks`, `first_ticks`) (STY 6.1.3).
- **D585** R3's speed limit `t_min` is an argument. `verdict.RegrowTicks(trough, level, bandBP, ratePerYearBP, ticksPerYear)` does the per-tick integer iteration with a carried remainder over `10 000 * ticksPerYear` of POP 3.8 and returns the ticks and whether the level is reachable. The replacement-only speed (`Renewal` times the leavers, funded by `EntryPoolShare`) is computed by the fact test from the pack (STY 5.3 S02, open question 2) and passed as `rate` (STY 6.1.1; FR-STY-036, 063).
- **D586** Seed rules: `SR1`, `SR2`, `SR3` take the planned `n` and the outside seeds in ascending order and return pass, the listed seeds and, for SR3, min, median, max; `n` is the number planned, a failed world is an outside seed (8.3.3); the median of an even count is the half-to-even mean of the middle two (FR-STY-076).
- **D587** Band rule `SetBand(values, side, m)`: headroom 2 500 bp for `m >= 40`, 5 000 for `10 <= m < 40`, refusal for `m < 10` and for a bound above the regime threshold it backs or a derived bound; the headroom quotient `range * h / 10 000` rounds half to even (FR-STY-006; 91 * 2 500 / 10 000 = 22.75 is 23) and the multiply is a range check against constants, no `math` import (O4); outward rounding to two significant digits (up for an upper bound, down for a lower, negatives away from zero, values under 100 kept) (STY 8.4.3, 8.4.4; FR-STY-077, 078).
- **D588** `Separate(healthy, provoked, kind)` returns the key value of 6.5.3: the integer midpoint of `t_hi` and `t_lo` rounded up, then up to a multiple of 5 for ticks or to two significant digits for a share or ratio, kept in `[t_hi+1, t_lo]`; `t_lo = t_hi+1` gives `t_lo`; `t_hi >= t_lo` is "does not separate" and leaves the key unset; low-is-bad detectors (R4, R7) are negated first (FR-STY-071, 074).
- **D589** `bandfile.go` parses the plain grammar of `bands/` (tables `[a.b]`, `unit`, `value`, `set_by`, `expects`, `#` comments) into keys in file order and validates the `set_by` shape `commit=<id>;config=<hash>;seeds=<a>-<b>` with the seed set exactly `1-50` (`1-10` for a tier L key; STY 12 "seeds"). It is a non-test file because the fact tests also read it; it duplicates the test-only reader of `support_test.go` on purpose (an `internal/` package cannot import a root test file). Source: STY 22, REF 7.1.5.
- **D590** The registry test (package `verdict`, relative paths `../../doc/specs` and `../../testdata`, testing 6.7, 10.4) parses `spec-stylised-facts.md` and the band files and runs the seven checks of STY 12 (fields, keys, shape, seeds, ordering, coverage of S01 to S165, closed sets) plus the equality of the priors `s14.recover_band_bp` and `r3.recover_bp` (FR-STY-001 to 005, 007, 009, 010, 072, 098).
- **D591** The ordering rule is data: `OrderingPairs` lists the pairs of 6.5.2 and `CheckOrdering(bands, regimes)` rejects a violation, including the implication: a pinned run of `r5.pinned_ticks` ticks is `60 * 10 000 / 365 = 1 643` bp of a year, at least `s16.pinned_share_bp` and `x4.pinned_share_bp` (FR-STY-072).
- **D592** `Check(name, conjuncts)` returns `STABLE`, `NOT STABLE` or `UNDETERMINED` by 7.2: a conjunct that failed or a detector `detected` is NOT STABLE; an unset B key, a detector `unknown`, a blind-spot field outside its bound (7.2.2) or a missing overlay is UNDETERMINED. These three words are the only place the word is used (FR-STY-095, 096).
- **D593** Records: `RenderVerdict` and `RenderStability` produce plain integer text in the fixed order of 8.5 (pack, scenario, fact ID, then region and role ascending), no float, no map order, no wall clock; goldens `testdata/golden/stylised/<pack>.txt` and `<pack>.stability.txt`, rewritten only with `-update` and never under `-race` (plan 1 D228's rule, mirrored) (FR-STY-084, 085, 087; NFR-STY-002).

Each re-runs its pack and seed (a run is a function of configuration and seed), uses a recording observer and run helper of its own in `stylised_helpers_test.go` (plan 18 D576 provides none; REF's copies in the root package are not importable), loads packs through `config.LoadFS` over `os.DirFS` of `testdata/chains` (the root `loadPack` and `plainTOML` are `_test.go` symbols of another package), consumes plan 18's `Tally`, `Window`, `Prices*` and `Classes`, converts IND results to `verdict` series inline, and is one test per group and pack (FR-STY-082).
