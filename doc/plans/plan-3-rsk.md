- **D2. The canonical order.** Route rows sort by (`From`, `To`, `Mode`) as region index, region index and mode index, store rows by (`Region`, `Class`) as region index and class index (spec 3.2.3, 12.1). The sort needs the configured region and mode order, so it is a method `(m *Risk) canonical(c *Config)` called from `Config.canonical` (`config.go`), as `Settlements` and `Tenure` have one each; the hash writes the sorted form (FR-CFG-089). `defaults.go` gets nothing: the module has no default.
- **D3. The keyed draws: this is where the spec is stale and the plan makes four choices.** spec-risk.md 3.4, 4.2, 6.2, 11.2, 11.4, 18.4 and RSK-S1 are written for one positional stream ("one word", "every later word of the run moves by one place", example A's PCG words). ADR 0008 (N-214, applied to `random.go`) replaced it with keyed streams, so a draw depends on its key and on no other draw. The plan appends four site constants to `random.go` (the value is the first eight bytes, big-endian, of SHA-256 of `economy-sim/site/<name>`, computed on this host and re-checked by the `Guard:` spacing test of 2^32 and by `models/wld/seed.py`): `siteRiskCommon` = `0x7becbb022be68d1a` (D13: tick, `id` = the `From` region, `sub` = `To * MaxModes + Mode`; one word), `siteRiskDispatch` = `0x7e59e8f556fe1651` (D14: tick, `id` = the shipment ID; keyed once per dispatched shipment, then one word per unit row of the path with a probability above 0, in path order, as `siteInform` is keyed once per view), `siteRiskStoreCommon` = `0x22650fb6363bd5bc` (D15 (i): tick, `id` = the region, `sub` = the store class; one word) and `siteRiskStore` = `0x85e20986fa93c736` (D15 (ii): tick, `id` = the agent, `sub` = the store class; one word per store instance, ascending). D15 needs two sites because a region ID and an agent ID share the `id` slot and a common row must not share a stream with an agent. spec-world.md 7.1.4 and 7.3 are edited in Phase 1 (E4). What stays: no word for a row with `P = 0` (FR-RSK-007) and no word for a unit row with no exposure (FR-RSK-034): it keeps the cost down and the neutrality of FR-RSK-005 exact. What is corrected as stale: 11.4 and example D (a scale of 0 no longer shifts any other draw, so the paired comparison is aligned either way and open question 9 is moot), the "words in order" wording, and `models/rsk/loss.py` parts 1 and 2 (the example words are regenerated from the keyed streams; the arithmetic of the other parts is unchanged). `TestDraws_KeyedNotPositional` pins the keys with vectors.
- **D4. The ledger reason.** `Loss` is appended to `internal/ledger/registry.go` as a goods sink with the pairing Transit-or-agent to boundary (`setTransit|setAgent` to `setBoundary`; the row of spec-ledger.md 7.2 allows no estate form and no money form, so the registry row has only `thingGoods`), code **36** in `reasonCodes` (`TestReasonCode_Pinned` fails until it is set), the name `ReasonLoss` in `event.go` and `ledger.go`'s `reasonNames`, and `riskReasons()` in `moduleReasons` after the credit branch (the `Modules` order, spec-world.md 5.2 row 3a: the boundary accounts are opened goods commodity-major in pointer order, N-226's open point for RSK, answered here). With the module off the ledger layout does not change, so `golden/off/` does not move. N-226 gets an update line; the position of the accounts is confirmed in Phase 1.
- **D5. State and tables.** `type risk struct` held as `w.risk`, nil unless `Modules.Risk` is non-nil. Derived and never saved: the rows resolved to indices at construction, a per-configured-edge list of (mode, row) pairs so a dispatch reads the rows of a path edge by edge in O(modes with rows) with no allocation, the effective probability per row, the tick's common outcomes (a scratch vector, spec 15.2), and the expected-loss table. Saved: the two scale lists (sparse, only values other than 10 000). The expected-loss table is a sorted slice of (from, to, mode, lossBP) with binary-search lookup (a read allocates nothing, FR-RSK-025); it is rebuilt at construction, at `SetRouteRiskScales` and at `setEdgeStatuses` (`regions_status.go:42`, one guarded call, H-12), never in a tick. The agent type gets no field (`TestAgent_HoldsNoMoneyQuantityOrRegion` keeps passing). The shipment record gets one field, `loss int64` (spec 15.1: "one field in the section of another spec").
- **D6. Step 4a is one guarded call.** In `send` (`transport_request.go:437`), after the record is built and before `t.next++`, `if w.risk != nil { s.loss = w.risk.strike(&s) }`: it walks the path by `NextHop` over the world's own table (no `Path` call in a tick, spec 4.1.1), reads the tick's common outcomes and takes the D14 words. A refused request never reaches `send` (every check of TRN 5.4 is before it), so FR-RSK-010 holds with no extra code, and with keyed streams a draw taken by one shipment cannot move another's.
- **D7. Step 0 is split around the guard (the plan's one change to TRN's order, owed to the held arrival).** The spec puts the loss before the traveller's region change, so that a trip account's loss is attributed to the origin (7.2.1). But `arrive` today runs the move first and holds the arrival for a retry when the guard refuses; a loss applied before a refused move would be applied again at the retry (a double loss) and the identity of 5.2.2 would break. So `moveTraveller` is split into the guard (`relocateRefusal` with the skips) and the move; the order in `arrive` becomes: guard (a refusal holds with **nothing applied**), step 0 (the loss, Transit account then the trip account), the move, the delivery. `deliverLine` reads the units lost of its line from the scratch so `Spoiled = Shipped - (held + lost)` still holds. Pinned by `TestArrival_HeldMoveTakesNoLossTwice` (Fix: no bug exists yet; a Guard:). If the owner prefers the loss after the move the attribution of a trip account moves from the origin to the destination (Q2).

## Gate economics

- Full gates (gate R and gate F, `check.sh`, `full.sh`) run **once per PR, on the final head**, with `GOMAXPROCS=8`, and **one gate run at a time on the host**: earlyoom kills the 20-plus GB root test binary when two share the machine (three gate F runs of POL PR B were killed at 19, 28 and 38 GB). While a gate runs, no other session starts one.
- During a phase, run only the focused tests and `go test -short -race ./...` (and `-run` on a phase's own tests); do not run gate R or F per phase, per commit or per fix.
- If a gate run fails, fix, then rerun only the failing package; the full gates are rerun once more on the final head if the fix touches non-test code outside that package.
- `gomu` only inside Docker with `--cpus=4 --memory=16g --memory-swap=16g -e GOMAXPROCS=4`, per new file, never on the host; it does not overlap a gate run.
- A scenario test that keeps per-tick snapshots must not keep them for every parallel seed (the S113 lesson): S126 to S131 keep counters and the events, not snapshots.
- `examples/realm` `TestServe_*` can time out under `-race` when several gate runs share the machine; a rerun alone settles it.
