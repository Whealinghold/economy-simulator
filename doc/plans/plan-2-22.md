## 1. Scope

**Builds** a second Go module, `otelobserver/` (module path `github.com/Whealinghold/economy-sim/otelobserver`), and the root `go.work` that joins it to the core for local development (`architecture.md` 2.6). One flat package, `otelobserver`, with these files: `doc.go`, `observer.go` (`Observer`, `New`, `Option`, `WithClock`, `Observe`), `catalogue.go` (the instrument table), `names.go` (the names table, attribute cache, intern tables), `accum.go` (the per-tick accumulators and their flush), `levels.go` (UpDownCounters, held gauges, `lastUnfed`, seeding), `events_core.go` and `events_stage2.go` (the handlers by event group), `snapshot.go` (`RecordSnapshot`), `spans.go`. Public identifiers: `Observer`, `New`, `Option`, `WithClock`, `(*Observer).Observe`, `(*Observer).RecordSnapshot`.
Every instrument of the catalogue (`spec-observability.md` 6.2.1, 6.2.2; `observability-and-logging.md` 5.3) whose events and snapshot rows exist in the root after plans 2 to 16, the spans of 6.6.5, the state of 6.6.1, the seeding of 6.4.2 for the levels of those instruments.

**Leaves out, with the owner:**
- The instruments of the Stage 3 modules (storage, employment, settlements, tenure, credit, capital, risk, fiscal, organisations, saving, technology, policy, insurance), and `economysim.transport.cargo.lost` (its field `ArrivedLine.Lost` is risk's): each module plan of Stage 3 appends its rows to `catalogue.go` and takes its name off the `notBuilt` list of the catalogue test (D644).
- Any change to the core module, except the one root drift test of Phase 9 (`catalogue_otel_copy_test.go`): no root file, no root test, no event, no snapshot field is touched. The core never imports OpenTelemetry (`architecture.md` 11.4; the existing `import_guard_test.go` keeps proving it).
- `RecordSnapshot` is a method the consumer calls; the world never calls it and the adapter never calls the world (`spec-observability.md` 6.2.2, 6.6.4).
- A Prometheus or OTLP exporter, a `MeterProvider` or an SDK choice: the consumer supplies the providers (rules 6.3). The first-consumer example that wires the adapter into a server is plan 24.
- The tests of NFR-OBS-003 and NFR-OBS-004: the table of 9.9 lists them under the adapter, but both are about the core (a counter built only when an observer was supplied; the allocations of `Snapshot`). They are root tests that exist since Stage 1 and not this module's; see Phase 1, owed edit 3, and Risks, item 4.
- The `Warn`s: the adapter has no logger and logs nothing (rules 7.1).

## 2. Decisions

- **D640. Layout.** `otelobserver/go.mod` declares `module github.com/Whealinghold/economy-sim/otelobserver`, `go 1.25`, requires the root module and the OpenTelemetry packages; `go.work` at the repository root has `use ( . ./otelobserver ./examples/inspector )` (`examples/inspector` is an existing Stage 1 module, and in workspace mode a module that is not listed fails to build; plan 24 adds `./examples/realm` and `./examples/colony`). The root module's files, tests and `go.mod` are untouched. Source: `architecture.md` 2.6; roadmap-v1 Stage 2 row; OBS 20.
- **D641. Dependencies.** API: `go.opentelemetry.io/otel`, `.../otel/metric`, `.../otel/trace`, `.../otel/attribute`, `.../otel/codes`, and `.../otel/metric/noop` and `.../otel/trace/noop` for a nil provider. Tests only: `.../otel/sdk`, `.../otel/sdk/metric` (with `NewManualReader`), `.../otel/sdk/trace/tracetest`. The root `require` is a placeholder pseudo-version (`v0.0.0-00010101000000-000000000000`) resolved by the `replace`; `go.work` carries `go 1.25`. One OpenTelemetry version for all, v1.38.0 (the newest release known to the author that is older than the two weeks of the contract; Phase 1 re-checks with `go list -m -versions` and records the final one). Until the first tagged release `otelobserver/go.mod` carries `replace github.com/Whealinghold/economy-sim => ../` so that `go mod tidy` works on its own; the replace is removed in the commit that tags `otelobserver/v0.1.0` (`architecture.md` 2.6). Source: `architecture.md` 2.6, 11.4; `testing.md` 6.6; rules 6.3.
- **D642. Constructor and contract.** `New(mp metric.MeterProvider, tp trace.TracerProvider, opts ...Option) (*Observer, error)`. A nil provider becomes the package `noop` provider, never a global one (`otel.GetMeterProvider` and `otel.GetTracerProvider` are never called). The scope name of both is the module path (rules 6.3, OBS 6.6.6). `New` returns an error only when the SDK refuses to create an instrument; after `New` nothing returns an error and nothing panics (rules 7.1). The type is documented as not safe for concurrent use, like the world. `*Observer` implements `economysim.Observer` and carries `var _ economysim.Observer = (*Observer)(nil)`. Source: OBS 6.2.2, 6.6.4, 6.6.6; rules 6.3, 7.1.
- **D643. One table.** `catalogue.go` holds `var catalogue = [...]spec{...}`: for each instrument its name, kind (counter, up-down counter, gauge, histogram), unit, one-line description and attribute keys, indexed by an unexported constant per instrument. `New` builds every instrument from it in one loop with `Int64Counter`, `Int64UpDownCounter`, `Int64Gauge` and, for the duration, `Float64Histogram`; no handler creates an instrument. The descriptions are written with the code (FR-OBS-050). Source: OBS 6.1.3, 6.2; rules 5.1 to 5.3.
- **D644. The catalogue test is staged.** `catalogue_test.go` holds the expected table as Go data (name, kind, unit, attribute keys) copied from OBS 6.2, because a test may not read outside its module (`testing.md` 10.2). It asserts the adapter's table equals the expected one minus a `notBuilt` list, that every name starts with `economysim.`, ends in no `_total` and holds no unit, that every instrument has a non-empty description, and that `notBuilt` names only rows that the table lacks (fails when a listed instrument is built, and when an expected row is neither built nor listed), the same staged form as FR-OBS-003. `notBuilt` starts with the Stage 3 rows of D655. Agreement of the Go copy with the spec table is checked by the two drift tests of Phase 9 (Risks, item 3). Source: FR-OBS-050; OBS 9.9.
- **D645. Series keys and attributes.** A series is a `cell{a, b, c, d int32}` of dense indices: a typed ID is its index, a closed-set constant is its index in a table of the adapter, an open string (`Reason`, a money flow ID) is interned. `names.go` builds from `WorldCreated.Names` or `WorldRestored.Names`, once, one `[]attribute.KeyValue` per kind (`economysim.commodity`, `.region`, `.role`, `.recipe`, ...); an `attribute.Set` is built the first time a cell is used and kept in a `map[cell]attribute.Set` per instrument, so the steady state allocates nothing and records with `metric.WithAttributeSet`. An index outside its table drops the sample (OBS 6.6.4). The intern table of an open string holds at most 1 024 values per attribute key and drops the sample beyond (a defence, since the names table has no flow IDs: Risks, item 2). No cell holds an `AgentID`, an order, a price, a tick or a quantity. Source: OBS 6.5.1, 6.6.3, 6.6.4; rules 5.4.1.
- **D646. Two kinds of accumulator.** The hot instruments (`market.orders`, `market.orders.rejected`, `market.trades`, `market.volume`, `estate.sold`: tens of thousands of events a tick, OBS 8.3) accumulate in dense `[]int64` arrays indexed by mixed radix over the sizes of the names table (the rejection reasons are interned to at most 32). Every other event-fed counter accumulates in a `map[cell]int64` (a few events per market or region per tick). Neither calls the SDK. Source: OBS 6.6.2; NFR-OBS-005.
- **D647. When the SDK is called.** Inside a step (between `TickStarted` and `TickEnded`) the accumulators fill and are flushed at `TickEnded`, each non-zero cell once; a Counter gets its sum, an UpDownCounter its net delta, a gauge its last value. A class-C or class-W event, and every event outside a step (a call between ticks, the construction events, the bucket at `Tick` -1, `AgentSpawned` of the initial agents), is flushed at once after the handler. A `TickEnded` with `Failed` true flushes what the adapter saw, records no duration, adds 1 to `economysim.world.step.failed` and runs no reset (D649). Source: OBS 6.3.1, 6.6.2; FR-OBS-055, 058.
- **D648. Levels and held gauges.** Every UpDownCounter keeps a shadow `int64` per cell (allowed by 6.6.1); seeding is done by difference, `Add(seed - shadow)`, so it is correct on first attachment and on a second `WorldRestored`. On a second `WorldCreated` or `WorldRestored` the adapter first adds `-shadow` for every cell under the old names table (so the SDK level returns to 0), then rebuilds the tables; `WorldCreated` carries no snapshot, so its levels stay 0 until `AgentSpawned`. A held gauge (the nine of OBS 6.3.6 that exist at this stage: `endowment.stock`, `household.own_use`, `external.price`, `market.clearing_price`, `belief.centre`, `belief.at_bound`; `rent.rate`, `settlement.class` and `technology.gain` are Stage 3) keeps its last value per cell and re-records every cell at `TickEnded`. The other event-fed gauges (`market.price_age`, `production.cost_anchor`) record when their event arrives and are flushed at `TickEnded` (every market emits every tick). After that step `WorldCreated` resets every shadow, accumulator and `lastUnfed`. Source: OBS 6.3.6, 6.4.1, 6.4.2, 6.6.1; FR-OBS-054, 060.
- **D649. The unfed level (6.3.1).** `lastUnfed []int64` and `seen []bool`, both of length regions times roles, from the names table. `UpkeepShortfall` adds `Unfed - lastUnfed[r,k]` to `household.unfed`, stores `Unfed` and marks the cell. At a `TickEnded` that did not fail, every unmarked cell with a non-zero last value adds `-lastUnfed`, is set to 0, and all marks are cleared. At a failed one nothing is reset. `WorldRestored` seeds both from `Roles[].Unfed`. Source: OBS 6.3.1; FR-OBS-053, 055.
- **D650. Which events feed which instrument at this stage.** One handler per event type; the mapping is the "Fed by" column of OBS 6.2.1 and nothing else, except that a field named there which a Stage 2 plan spells differently is read from the root as built. Core (Stage 1): `TickStarted`, `TickEnded`, `OrderPlaced`, `OrderRejected`, `TradeExecuted` (also `estate.sold` where `Seller` is below `len(Names.Regions)`, N-310 item 2), `MarketCleared` (clearing price, price age, unmatched, cost anchor), `BeliefsUpdated`, `RecipeExecuted`, `RecipeRefused`, `RecipeAbandoned`, `ProductionHalted`, `UpkeepShortfall`, `AgentSpawned`, `AgentBankrupted`, `WeightChanged`, `RoleChanged`, `EntryLimited`, `BoundaryFlow`, `WearApplied`. Stage 2: `AgentRelocated` (plan 3), `WantShortfall` (5), `MoneyFlowLimited` (6), `EndowmentChanged` and `EndowmentAdjusted` (9), `OwnUseChanged` (10), `PopulationChanged` (11), `ShipmentDispatched` and `ShipmentArrived` (12), `RumoursServed` (13), `MigrationStarted` and `MigrationReviewed` (14), `ContractFormed`, `ContractSettled` and `MerchantsPlanned` (15), `OutsideTraded` (16). `EstateOpened`, `ReliefPaid`, `MoneyFlowEnded`, `MoneyFlowScaled`, `PopulationScaled`, `OutsideEnded`, `OutsideShocked`, `ContractRound`, `ShipmentRejected`, `TransitFactorChanged`, `YieldShocked`, `EdgeStatusChanged` and the other events feed no instrument (OBS 6.3.5); the exhaustiveness test (D656) lists them as ignored. Source: OBS 6.2.1, 6.3.5.
- **D651. Dispatch under the lizard limits.** `Observe` switches on the three hot types first, then calls `observeCore`, `observeMarketing` ... in a fixed chain of group functions of at most ten cases each (each returns whether it handled the event), so no function exceeds `-C 10`. An unknown type is ignored (the contract of `Observer`, so that a new event is not a breaking change). Source: `observer.go` contract; OBS 6.6.4; plan-2-0 gates.
- **D652. The clock.** `WithClock(func() time.Time)`, default `time.Now`, is read twice per step (`TickStarted`, `TickEnded`) and nowhere else; it feeds `economysim.world.step.duration` (seconds as `Float64`). Tests pass a fake clock; the production default is the only wall-clock read of the module and the only one allowed (OBS 6.6.3: "anything that depends on the wall clock other than the duration of a step" is forbidden; `AGENTS.md` bars `time.Now` from the core, which this module is not). Source: OBS 6.2.1 row 1; `testing.md` 10.2.
- **D653. Spans.** `RunStarted` starts `economysim.run` from `context.Background()` and keeps the context; `TickStarted` starts `economysim.step` as a child of the run context if a run is open, else a root span, with the attribute `economysim.tick`. `TickEnded` sets the attributes `economysim.orders.placed`, `economysim.orders.rejected`, `economysim.trades` and `economysim.volume` (read from the D646 accumulators before they are flushed and zeroed), sets status `codes.Error` when `Failed`, and ends the span; `RunEnded` ends the run span, error when `Failed`. If a `TickStarted` or `RunStarted` arrives while the previous step or run span is still open (a panicked step, FR-OBS-013), the open span is ended with status `codes.Error` first. A class-E event inside a step is `AddEvent("economysim.<event>", ...)` on the step span with its small scalar fields (strings from the names table, counts, bools; never a slice, never an `AgentID`); the events that qualify are the class-E rows of OBS 4.1 that are in D650. An event outside a step goes to the run span if one is open and is dropped otherwise. `WorldCreated` and `WorldRestored` are not span events. The attribute and event names are this plan's (the spec fixes the content, not the names): owed edit 1. Source: OBS 6.6.5; rules 6.1 to 6.3; FR-OBS-055.
- **D654. `RecordSnapshot`.** Takes a `Snapshot` by value, decodes attributes from the snapshot's own `Names`, records each instrument of OBS 6.2.2 once per series from the rows named, and nothing else. Rules: `Has*` flags gate `welfare.ratio`, `welfare.ratio.households`, `wage.observed`, `role.expected_ratio`, `role.viable` (1 or 0); `welfare.floor_held` is `HeldByFloor * 10 000 / Households` computed with `math/bits` 128-bit multiply and divide, absent where `Households` is not above 0 or `HeldByFloor` is negative; `recipe.in_progress` records each `Jobs[]` row; `money.supply` records the sectors `households`, `pool` and, where `RegionRow.MoneyContract` exists, `contract` (`treasury` is Stage 3); `market.stock` the holders `agents` and `estate` (`treasury` is Stage 3). An ID outside the snapshot's names, a negative region and a nil slice drop or skip the row; the method never panics and never records a series outside the bound of 6.5. `estate.sold` is event-fed and is therefore not in this method although OBS 6.2.2 lists it there: owed edit 2. Source: OBS 6.2.2, 6.1.2; FR-OBS-052, 104.
- **D655. The staged catalogue.** Built here: every instrument of OBS 6.2.1 and 6.2.2 that no Stage 3 module owns, counted by `TestCatalogue_NotBuiltIsExact`, which prints the figure, the 6.2.2 ones being `production.pending`, `recipe.in_progress`, `market.stock`, `estate.at_floor`, `ledger.lots`, `money.supply`, `welfare.ratio`, `welfare.ratio.households`, `welfare.floor_held`, `welfare.clamped`, `wage.observed`, `household.privation.max`, `role.expected_ratio`, `role.viable` and `role.agents`; `estate.sold` is event-fed (D654). The `notBuilt` list (Stage 3): `storage.limited`, `store.count`, `room.fill`, `hire.*`, `labour.unmatched`, `vacancy.unfilled`, `settlement.*`, `rent.*`, `title.transfers`, `credit.*`, `facility.*`, `risk.strikes`, `transport.cargo.lost`, `store.lost`, `fiscal.*`, `right.refusals`, `control.clamped`, `saving.*`, `technology.*`, `policy.*`, `insurance.*`, `body.*`. Phase 9 prints the exact count and the series bound per group for the test world. Source: OBS 6.2; roadmap-v1 Stage 2 and 3 rows.
- **D656. Test world and harness.** Tests build their world in Go (`miniConfig()` in `config_test.go`, from the `economysim.Default*` constructors, built in the test, larger than the root's `example_test.go` world: three regions, five commodities, four roles, two seasons) because the module cannot read the core's `testdata/`. Module-dependent behaviour (resources, transport, migration, merchants, external, population, subsistence, demand, money flows) is driven by synthetic events built in Go, one of every type of D650, with in-range and out-of-range IDs, so that the adapter's tests do not depend on a module overlay of the core. The harness (`harness_test.go`) holds a `sdkmetric.ManualReader`, a `tracetest.SpanRecorder`, a fake clock that advances 1 ms per read, and `collect()`, which returns every point as `map[name]map[attributeSetString]int64`. No test sleeps, reads the network or reads outside the module. Source: `testing.md` 6.6, 10.2; OBS 9.9.
- **D657. The call counter.** `countmeter_test.go` wraps the SDK meter: each instrument returned embeds the SDK's and counts `Add`, `Record`, each into a `map[name]int`. It is how the "once per series per tick" row is tested (a count of SDK calls, not a count of points, which the SDK aggregates). Source: OBS 9.9 row "volume"; NFR-OBS-005.
- **D658. The restore test.** `restore_test.go` runs a real world from `miniConfig()` with adapter A attached from `NewWorld`, takes a `Checkpoint` at tick N, builds `RestoreWorld(cfg, checkpoint, WithObserver(B))` with a fresh reader for B, runs M further steps on both, and compares at the end of the first complete step after the restore, for every UpDownCounter and every gauge fed every tick, the A and B values; sparse held gauges are compared from the first event of each series. Counters are not compared (B starts at 0). N is taken at 0, mid-run, and after a call between ticks. Source: OBS 6.4; FR-OBS-054; `testing.md` 6.2.
- **D659. Gates for this module.** From `otelobserver/`: `gofmt -l .`, `go vet ./...`, `staticcheck ./...`, `go test -short -race ./...`, `go test -race -covermode=atomic -coverprofile=coverage.out ./...` with at least 80% statement coverage (`testing.md` 9.1), `go mod tidy` with no diff, `lizard -l go -C 10 -a 8 -L 100 -w .`. The core's gates are run again from the repository root with `go.work` present, R and F exactly as `plan-2-1` D229 states them, plus `gofmt -l .`, `go vet ./...`, `staticcheck ./...` and `go mod tidy` with no diff, to show nothing moved; the `otelobserver` module's own coverage run is separate (above). The module has no `internal/` package, so the contract's mutation pass has no target; `gomu` (Docker, `--cpus=4 --memory=16g --memory-swap=16g -e GOMAXPROCS=4`, `--workers 4`) is run per file on `levels.go` and `snapshot.go` all the same, because they hold the rules that a count cannot show. Source: plan-2-0 gates; `testing.md` 9.1, 9.4.
